# WebMCP Integration

bAssistant implements multi-standard WebMCP support to maximize compatibility with visiting AI assistants, inspector extensions, and client scripts.

## Registered Standards

On `register()`, `WebMCPProvider` publishes the same **17 tools** across six discovery surfaces at
once, so any inspector, extension, or script finds them regardless of which protocol it probes:

1. **`document.modelContext`**: The primary Chromium imperative surface. When the native flag
   (`chrome://flags/#enable-webmcp-testing`) exposes `registerTool`, every tool is registered natively
   with an `AbortController` signal; otherwise a polyfill (`getTools`, `listTools`, `registerTool`,
   `executeTool`) is installed. The promise returned by native `registerTool` is captured and its
   rejection swallowed, and `unregister()` aborts each controller with a reason (`abort('unregister')`),
   so tearing down the provider never produces an unhandled `AbortError`.
2. **`navigator.modelContext`**: Draft-era imperative interface, defined with the same tool object.
3. **`navigator.modelContextTesting`**: Flag-gated testing interface used by inspector extensions.
4. **`window.webmcp` and `window.modelContext`**: Direct JavaScript bridge objects offering
   `listTools()`, `getTools()`, `callTool(name, args)`, and `executeTool(name, args)`.
5. **Declarative hidden DOM forms**: A display-hidden, `aria-hidden` container
   (`#webmcp-declarative-container`) synthesizes one `<form toolname="…" tooldescription="…">` per
   tool, each with an `<input toolparamdescription="…">` for every top-level parameter, for DOM-based
   audits.
6. **`postMessage` (JSON-RPC 2.0)**: A `window` `message` listener answering `tools/list` and
   `tools/call` (with aliases `listTools`, `getTools`, `callTool`, `executeTool`, and the
   `WEBMCP_*` / `MODEL_CONTEXT_*` message types). Replies use the standard
   `{ content: [{ type: 'text', text }] }` payload and error code `-32603`.

**Ready events:** on registration it dispatches both `webmcp:ready` and `modelcontext:ready` custom
events on `window`, each carrying `detail: { tools }`.

> Only `get_tool_usage_prompt` and `get_reference_url` set `readOnlyHint: true`. All other tools leave
> the hint unset (they are not flagged read-only).

**Lifecycle:** the provider is constructed **once** in `App.tsx` and torn down only on unmount. Its
`ToolContext` closures read the latest handlers through a ref, so message and reference-URL changes
never re-register (or mid-session abort) the tool set; `updateWebMCPContext()` swaps closures in place.

## Tool Suite Overview

| Tool | Parameters | Description |
| :--- | :--- | :--- |
| `get_tool_usage_prompt` | `{}` | Read-only: returns the official agent operating guide explaining how to use every other bAssistant tool (retrieval, canvas, chat, PDF export, conventions). |
| `get_reference_url` | `{}` | Read-only: returns a comma-separated list of external reference/documentation URLs cached in the browser session. |
| `get_chat_history` | `{}` | Returns recent dialogue history with user messages prefixed by `user:`. |
| `chat_post` | `{ text: string }` | Posts textual responses, markdown, or status updates to the chat area for the visiting LLM. |
| `canvas2d_draw_shapes` | `{ shapes: object[] \| string }` | Appends structured Canvas2D shapes (rectangles, ellipses, diamonds, text, stickers, freehand `freedraw`) rendered with Rough.js hand-drawn sketching, plus fluid Bézier connectors bound via `startId`/`endId`. Supports optional artistic styling (`roughness`, `fillStyle`, `subtitle`, `palette`). Accepts an array or a JSON string. |
| `canvas2d_inspect_shapes` | `{}` | Returns the active scene graph and an ASCII topology graph for visiting agent self-inspection. |
| `canvas2d_modify_shape` | `{ nodeId: string, newLabel?: string, fillColor?: string, strokeColor?: string, x?: number, y?: number }` | In-place shape editing (label, position, colors) while keeping connected arrows attached. |
| `canvas2d_clear` | `{}` | Clears all shapes from the Canvas2D scene graph. |
| `export_pdf` | `{}` | Generates and downloads a publication-quality session PDF report combining canvas snapshot and dialogue. |
| `canvas_draw` | `{ command?: object, commands?: object[] }` | Legacy: draws shapes (`rect`, `circle`, `line`, `text`, `graph`) in single or batch mode. |
| `draw_diagram` | `{ nodes: object[], edges: object[], title?: string, clearFirst?: boolean }` | Legacy: draws a connected flowchart with nodes and labeled edges. |
| `canvas_clear` | `{}` | Clears all drawings from the canvas. |
| `search_document` | `{ query: string }` | Queries IndexedDB using client-side BM25. Removes stop words and returns the top 3 pages. Recommend passing targeted keywords rather than conversational questions. |
| `clean_document` | `{}` | Purges IndexedDB tables and resets document UI. |
| `search_web` | `{ query: string }` | Live DuckDuckGo results via the same-origin `/api/websearch` proxy. Returns `{ results, fetchedAt, source }`; on failure `{ results: [], unavailable: true }` rather than fabricated data. |
| `search_research` | `{ query: string }` | ArXiv papers via the same-origin `/api/arxiv` proxy, with `fetchedAt`/`source` and honest unavailability. |
| `calculate` | `{ expression: string }` | Evaluates decimal math with floating-point correction. |
