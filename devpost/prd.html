Product Requirements Companion — Status: Approved

bAssistant

Zero-backend React SPA on Cloudflare Pages. Empowers visiting LLMs via WebMCP with live canvas diagramming, in-browser LiteParse + BM25 local doc querying, decoupled live voice, and free research tools.

The Core Journey

  1. Arrival: the UI renders the 20/80 layout in the chosen theme; canvas and chat start blank.
  2. Document ingestion (optional): a Doc/PDF < 2MB is parsed pagewise by LiteParse (WASM) and indexed into a client-side BM25 index in IndexedDB; the upload area shows file name, page count, and an "Indexed" badge. Files ≥ 2MB or unsupported trigger a rejection popup.
  3. User input: messages typed into the chat are shown with a user: prefix.
  4. Agent connection & tool discovery: a visiting LLM connects via browser-native WebMCP and calls get_tool_usage_prompt first to learn the intended workflow.
  5. Tool execution: the LLM queries history and calls search_document (BM25), search_web (Tavily-first), search_research (ArXiv), or calculate.
  6. Multimodal output: the LLM streams its explanation into the 40% chat area and renders live diagrams on the top 60% canvas.
  7. Canvas & storage control: clear the canvas via UI button or tool; run clean_document to wipe stored chunks and reset the upload area.

Screens and Layout

A responsive single-page cockpit filling 100% of the viewport:

Left Sidebar (20% width)

  • Section 1 (Top) — Branding: title "bAssistant", transparent theme-aware logo, and a 2-tiered right-aligned action cluster (Tier 1 [voice], [tips], [theme]; Tier 2 ⚙️ user preferences).
  • Section 2 — File Upload: dropzone + picker for Doc/PDF strictly under 2MB; shows filename, page count, and "Indexed" badge.
  • Section 3 — Reference URLs: enboldened REFERENCE URLS header with count badge (up to 10); + Add opens a reachability-verification modal before caching.
  • Section 4 (Bottom) — Session Highlights: collects starred dialogue messages for instant revisit.

Main Workspace (80% width)

  • Top 60% — HTML Canvas: interactive drawing surface with toolbar buttons ("Clear Canvas", etc.) that mirror exposed WebMCP tools.
  • Bottom 40% — Chat Area: scrollable dialogue in Lora longform reading typography with auto-scroll, a bottom text input, and a header bar docking the compact VoiceLiveController (mic toggle, live status pill, transient caption preview, settings gear).

Modals & Overlays

  • UserPreferencesModal — manage up to 10 preferences (max 120 chars each) in localStorage['b_user_preferences'].
  • VoiceSettingsModal — configure the Gemini key (AES-GCM-256 encrypted), Live audio model (gemini-3.8-live default), Subagent model (gemini-3.5-flash-lite), and Studio Voice (Puck, Charon, Kore, Fenrir, Aoede).
  • AudioPreflightModal — 1-second mic permission + volume meter check before connecting.

Features and Behavior

1. Document Upload & In-Browser Indexing
  • Capability: ingestion of Doc/PDF strictly < 2MB.
  • Processing: client-side LiteParse (WASM) page chunking, with stream decompressor fallback, hex string decoding (<...> Tj, [...] TJ), and in-browser DOCX PKZip word/document.xml decompression.
  • Storage: chunks + BM25 index in IndexedDB.
  • Feedback: valid → filename, page count, "Indexed"; invalid (≥ 2MB or unsupported) → notification popup with the exact reason.
2. Chat Conversation & History
  • Input: bottom text input + send button; user messages rendered with a user: prefix.
  • Humanized rendering: headings (H1–H6), lists, fenced code blocks, blockquotes, and inline tokens (**bold**, *italic*, `code`, links) render as styled elements without raw markdown syntax.
  • Symbol humanization (symbolHumanizer.ts): LaTeX arrows/operators → clean Unicode (→, ⇒, ≤, ≠, ×); currency ($100, $50M) preserved; multi-line sequence flows kept on separate lines.
  • Retrieval & posting: agent reads context via get_chat_history and appends text via chat_post.
3. Live HTML Canvas Rendering & Scene Graph
  • Structured Canvas2D shapes (rectangle, ellipse, diamond, text, sticker) + perimeter-docked connectors (arrow, line) rendered with Rough.js hand-drawn sketching.
  • Fluid cubic Bézier connectors with tangent-aligned arrowheads; tactile paper backdrop; Risograph color harmonies (terracotta, warm cobalt, sage mint, sunflower gold, plum).
  • Edge-to-edge perimeter docking; fitToContent auto-centering; drag-to-pan + cursor-pinned wheel zoom.
  • Universal medium dark yellow (#d97706) bold labels at topCenter and on connector pills for dual-theme contrast; live theme sync via MutationObserver.
  • Toolbar: New Session, Fit View, Reset View, Clear Canvas, Export PDF — also callable as WebMCP tools.
4. Client-Side PDF Generation & Session History
  • Active session persisted in bAssistantDB (session_turns, session_meta) across reloads; Session History Modal to browse/restore/export/delete past sessions; "New Session" restart.
  • Sequential turn-by-turn A4 export (exportSessionPdf): branding logo, session title/ID/timestamp, TURN X [HH:MM] badge, USER INQUIRY, canvas snapshot (aspect preserved), AI DELIBERATION.
  • Blank-session validation blocks export and alerts the user.
  • Markdown humanization for LLM content; Bengali & Hindi complex-script rendering via Canvas2D shaping into jsPDF; 10mm multipage buffer; mandatory centered AI disclaimer footer AI generated analysis, verify before applying. with Page X of Y.

6. Long-Dwell Reading Comfort & Session Engagement
  • Warm dual themes via a semantic CSS token layer (light = paper & navy ink; dark = warm ink surfaces); all cockpit components adhere to it.
  • First-load onboarding WelcomeModal (upload → connect agent → ask → highlight → maximize → export); dismissal persists; sidebar "tips" re-opens.
  • Chat popup maximize (⤢) into a full-screen reader; A-/A+ font steps (15/17/19px) persisted; 2px reading-progress bar.
  • Session Highlights (☆/★) collected in the sidebar; click scrolls the dialogue to it.
  • Alive-but-calm feedback: thinking pulse, 0.18s entrance fades, per-message copy, drag-over highlight, session strip — all motion disabled under prefers-reduced-motion.
7. SEO, Crawler Discoverability & Indexing
  • <meta name="description">, Open Graph + Twitter cards, theme-color, and JSON-LD WebApplication schema.
  • Semantic <noscript> outline for non-JS crawlers.
  • Static plain-text public/robots.txt (prevents SPA fallback syntax errors) and public/sitemap.xml.
8. Keyless Tavily Web Search with Automatic DuckDuckGo Fallback
  • Primary: Tavily Search API (POST https://api.tavily.com/search, X-Tavily-Access-Mode: keyless) for clean, ranked, scored snippets.
  • Two-tier proxy fallback in the same-origin /api/websearch layer (dev middleware + Cloudflare Functions); on error/429 it falls back to DuckDuckGo HTML scraping.
  • Honest metadata: every outcome carries source: 'tavily' | 'duckduckgo' and an ISO fetchedAt.
9. Bidirectional Full-Duplex Live Voice Mode & Pluggable Architecture
  • Tier 1 (gemini-3.8-live): 16 kHz AudioWorklet capture, 24 kHz gapless PCM playback, zero-latency barge-in.
  • Tier 2 (gemini-3.5-flash-lite): background subagent invoked via the async generate_diagram_and_explanation bridge tool; the bridge returns immediately while the subagent clears/draws the canvas and posts the explanation to chat + IndexedDB.
  • Ephemeral spoken chitchat: live speech stays in the stream and HUD captions, never in the persisted dialogue or PDFs.
  • Multi-provider subagents (ISubagentProvider): Google Gemini, OpenAI (gpt-6-luna, gpt-5-nano), Mistral AI, Requesty AI, Ollama Cloud — plus custom model IDs, per-provider AES-GCM-256 encrypted slots, and a mandatory in-memory Quick Test before saving Tier 2 changes.
  • Encryption: 256-bit AES-GCM via window.crypto.subtle, non-extractable keys in IndexedDB (bassistant_secure_vault), ciphertext __BASSISTANT_ENC__:v1:... in localStorage.
  • Prompts (src/voice/prompts.ts): templates for both tiers, runtime temporal anchoring ({current_date}), user-preference injection, and clear separation of bridge tools vs client WebMCP tools.
10. User Preferences Engine (Browser Storage & WebMCP)
  • Up to 10 preferences (max 120 chars each) in localStorage['b_user_preferences'], managed via UserPreferencesModal (live X / 120 and X / 10 counters).
  • Dual consumption: injected into the Tier 2 subagent prompt and exposed via get_user_preferences.
  • Background task tracking (src/voice/tasks/taskManager.ts): bassistant_task_ IDs, lifecycle queued → in_progress → completed/failed, sessionStorage (bassistant_background_tasks, LRU 20), the get_background_task_status voice tool, and a reactive Voice HUD badge.
  • Voice HUD modals bound to the semantic token layer; reliable teardown — session.conn.close(1000) plus an isSessionActiveRef guard so trailing events never flip the UI back to "Live Listening".
11. DuckDuckGo Fallback Parser Reliability
  • Correct pairing: each result's snippet is read from the same block as its title/link — never by array position.
  • Clean results: ad/redirect anchors excluded; only http(s) URLs after uddg unwrapping.
  • Honest failure: a challenge/bot-wall or non-OK response surfaces as unavailable: true, never an empty success. A genuinely empty page may still return an empty list.
  • Plain text: titles/snippets are tag-stripped and entity-decoded (named + numeric). No change to the result shape or the Tavily path.

Acceptance criteria:

  • Challenge/anomaly response yields unavailable: true (never empty success).
  • Each snippet belongs to its own block (regression covers skipped anchors / count mismatch).
  • Ad/redirect URLs never appear; non-http(s) decoded URLs dropped.
  • An empty query returns [] without a network request.

States and Boundaries

  • Initial State: canvas blank; chat blank; empty dropzone; theme from the selected mode.
  • Onboarding State: first load shows the WelcomeModal; dismissal persists; "tips" re-opens it.
  • Document Loaded State: upload box shows file name, page count, green "Indexed" badge.
  • Document Cleaned State: clean_document wipes IndexedDB and resets the upload box.
  • Error State (File Rejected): popup for ≥ 2MB or unsupported type; input resets cleanly.
  • Error State (Blank Export Blocked): modal when exporting an empty session.
  • Persistence: document chunks and BM25 index persist in IndexedDB until cleared.

Product Decisions

  • Framework: React SPA on Cloudflare Pages — fast, zero-backend, client-side hosting.
  • Parser: LiteParse (WASM / stream decompressor) with natural 1:1 per-page chunking.
  • Search paradigm: BM25 lexical index in IndexedDB (stop-word removal, keyword guidance, top-3 retrieval) instead of remote vector embeddings — private and low-overhead.
  • Canvas: persistent Canvas2D scene graph, perimeter docking, multi-tier palette, ASCII topology inspection.
  • Reporting: client-side jspdf packaging canvas diagrams + formatted dialogue.
  • WebMCP: standard browser-native implementation; no custom in-page inspector UI.
  • Chat protocol: user:-prefixed prompts exposed to visiting models via WebMCP.
  • Reading typography: Lora serif (17px, 1.75 line-height, ~72ch measure) with auto-scroll.
  • Search: keyless Tavily AI primary, DuckDuckGo fallback.
  • Voice: decoupled dual-tier topology (gemini-3.8-live + gemini-3.5-flash-lite) to avoid audio latency and token bloat.
  • Voice persistence: ephemeral chitchat keeps chat/PDFs executive; only substantive subagent knowledge is archived.
  • Controllers: three custom hooks (useSessionController, useDocumentController, useVoiceOrchestrator) keep App.tsx a clean composition root.

Deferred From the POC

  • Sidebar Section 3 features (currently blank).
  • Multi-file collections and files ≥ 2MB.

Non-Goals

  • Server-side database or cloud file processing.
  • Direct generative image/video AI APIs (DALL·E, Midjourney, …).
  • Embedded API-key billing or LLM proxy servers (the visiting agent drives interactions).
