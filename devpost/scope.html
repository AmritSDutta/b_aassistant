WebMCP Browser Assistant

A zero-backend, single-page browser environment that empowers visiting LLMs with free WebMCP tools for live HTML canvas diagramming, local document querying, and free-tier web/academic research.

The Unique Kernel

Instead of paying for expensive multimodal generative models or backend infrastructure, this single-page app acts as a browser-native tool provider via WebMCP and an AI cockpit. Any visiting LLM can immediately draw interactive diagrams live on an HTML canvas, search free external knowledge sources with keyless Tavily AI search (falling back to DuckDuckGo), query user documents kept strictly in local browser storage, and conduct bidirectional full-duplex voice interactions using Gemini Live with a pluggable provider architecture.

Who It's For

Anyone who wants to learn, research, and explore any topic with AI in a cost-efficient, visually rich manner using their own affordable LLM — without sacrificing privacy or paying for high-tier generative image services.

The Core Loop

  1. The user opens the single page to investigate any topic (and optionally uploads a Doc or PDF < 2MB, pagewise-chunked in-browser using LiteParse and indexed with a client-side BM25 index in local storage).
  2. The user connects with the assistant via standard text prompts, visiting WebMCP agents, or bidirectional full-duplex voice mode (Tier 1 gemini-3.8-live audio orchestrator).
  3. The LLM calls free research tools — primary keyless Tavily AI search with automatic DuckDuckGo fallback, ArXiv search — and local document tools (querying the BM25 index) to gather information.
  4. Spoken dialogue is processed live with transient HUD captions (ephemeral, not cluttering dialogue notes), while substantive diagramming and detailed technical breakdowns are generated by the Tier 2 subagent (gemini-3.5-flash-lite). The subagent clears and draws fresh diagrams on the top 60% canvas and posts structured markdown explanations into the bottom 40% chat area (persisted to IndexedDB turns).
  5. The user absorbs the text and visuals together and continues the dialogue.

Split strictly 20% (left sidebar) / 80% (right workspace: 60% canvas, 40% chat). Visiting agents interact with the page purely through the exposed WebMCP tools.

Inspiration & Identity

  • Mood / Feel: Clean, utilitarian, responsive split-screen cockpit for AI-augmented research and visual thinking — featuring an artistic editorial illustration canvas engine rather than rigid flowchart software.
  • Visual Structure: Left 20% branding / file upload / reference URLs / session highlights; right 80% artistic HTML canvas (top 60%, Rough.js hand-drawn sketching, fluid Bézier connectors, paper textures, Risograph color harmonies) and Lora-typography chat (bottom 40%).
  • Warm dual themes: light = warm paper & navy ink; dark = warm ink surfaces (never cold blue-black), driven by a semantic CSS token layer for comfortable long sessions.

Why This Matters to the Learner

Enables a practical, genuinely beneficial tool for the community that proves WebMCP's potential in the browser: running multimodal interactions on cheap models, keeping all user data strictly local, and using free-tier tools rather than costly subscriptions.

What "Working" Looks Like

A user opens the single page and activates WebMCP Inspector testing mode. The inspector shows the exposed tools registered and operational:

  • get_tool_usage_prompt — read-only, zero-arg: returns the agent operating guide (agents call it first).
  • get_reference_url — read-only, zero-arg: comma-separated stored reference URLs (up to 10 verified).
  • get_user_preferences — read-only, zero-arg: stored user preferences as a string array (up to 10 items, max 120 chars each).
  • search_web — Tavily AI keyless search (primary) with automatic DuckDuckGo fallback.
  • search_research — ArXiv search.
  • calculate — decimal math calculations.
  • search_document — searches uploaded doc content in IndexedDB via the BM25 index.
  • clean_document — removes stored content from IndexedDB.
  • canvas2d_draw_shapes / canvas2d_inspect_shapes / canvas2d_modify_shape / canvas2d_clear — structured scene-graph drawing, inspection, and editing.
  • export_pdf — downloadable publication-quality PDF combining logo, canvas diagram, multipage dialogue, and a mandatory AI disclaimer footer.
  • canvas_draw / draw_diagram / canvas_clear — legacy drawing tools.
  • chat_post / get_chat_history — stream text into the chat area and read dialogue context.

A test run demonstrates a visiting agent calling these tools, retrieving data, updating chat, and drawing on the canvas live.

CUT (Explicitly Excluded)
  • Files ≥ 2MB: strictly rejected; only Doc/PDF files under 2MB are supported.
  • MCP server endpoint integration: operates 100% in-browser via WebMCP client protocols (document.modelContext, navigator.modelContext, window.webmcp, postMessage) without external backend SSE/stdio MCP servers.
  • Image, audio, or video data integration: ingestion is focused strictly on text documents (.pdf, .docx, .doc) and public reference URLs.
  • Server-side database / backend servers: browser storage only; zero server footprint.
  • Direct generative image/video AI APIs: eliminated in favor of fast, free programmatic HTML canvas drawing.
  • Built-in paid LLM billing/routing: visiting-agent connectivity is handled by the user's environment/agent via WebMCP.

Improvement — Search Fallback Reliability (2026-10-23)

The free DuckDuckGo fallback behind search_web should be correct and trustworthy, not merely "usually works". Today the fallback parser is untested, can mis-pair snippets with the wrong result, lets ad/redirect links through, and reports a DuckDuckGo bot-wall page as a successful empty result. This improvement tightens the fallback so its output can be trusted and its failures are honest.

IN NOW
  • Extract a pure, unit-testable HTML parser (parseDdgHtml) out of the fetch wrapper.
  • Pair each snippet with its own result block instead of by array position.
  • Drop DuckDuckGo ad/redirect anchors from results.
  • Only surface http(s) result URLs; discard anything else after redirect unwrapping.
  • Treat a challenge/bot-wall page as an unavailable failure instead of an empty success.
  • Harden request headers and expand HTML entity decoding; add hermetic tests for the parser and the failure path.
CUT (Explicitly Excluded)
  • Paid search APIs; a third fallback provider.
  • Response cache; per-request retry/backoff; de-duplicating the dev/prod fallback orchestration.
