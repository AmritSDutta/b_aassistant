Technical Spec Companion — Status: Approved

bAssistant — Technical Blueprint

Zero-backend React + Vite SPA on Cloudflare Pages. Multimodal WebMCP tool provider with LiteParse WASM, IndexedDB BM25 search, decoupled live voice, and an HTML canvas graphics engine.

How This Works, In Plain Language

  1. The page renders a 20/80 layout: a left sidebar (branding + theme toggle, file upload, Reference URLs manager for up to 10 verified links, Session Highlights) and an 80% main area split into a top 60% canvas and bottom 40% chat.
  2. Uploading a Doc or PDF (< 2MB) runs LiteParse inside the browser via WebAssembly — page-by-page extraction with stream-decompressor fallback, hex PDF token decoding (<...> Tj, [...] TJ), and DOCX PKZip word/document.xml decompression. A client-side BM25 indexer scores the text and stores chunks + index in IndexedDB.
  3. Chat messages are tagged with a user: prefix and kept in application state.
  4. A Unified WebMCP Provider registers 18 tools on six discovery surfaces: document.modelContext, navigator.modelContext, window.webmcp, hidden DOM tool forms, ready custom events, and window.postMessage JSON-RPC 2.0.
  5. A visiting LLM, extension, or inspector discovers the tools — including get_tool_usage_prompt (read-only guide, call first), get_reference_url, get_user_preferences, search_document, clean_document, get_chat_history, the canvas2d_* scene-graph tools, export_pdf, the legacy canvas_draw/draw_diagram/canvas_clear, chat_post, calculate, search_web, and search_research.
  6. The entire application contains zero server code, compiles to static assets, and is deployed to Cloudflare Pages.

System Architecture & Data Flow

Traces prd.md > The Core Journey: load → optional file ingest → prompt → WebMCP discovery → tool execution → multimodal output → cleanup. The only non-browser code is the thin same-origin /api layer (Vite dev middleware + Cloudflare Pages Functions) for web/ArXiv search and CORS-restricted provider calls.

Stack

  • Language & Framework: TypeScript, React 18/19 — standard component model, fast rendering, strict types.
  • Build: Vite — fast HMR, static export to dist/ for Cloudflare Pages.
  • Styling: Tailwind over a semantic token layer (src/index.css: --paper/--panel/--card/--ink/--line + accents), one warm palette that swaps per theme.
  • Artistic Canvas: roughjs ^4.6.6 · MIT for hand-drawn sketching at ~11 kB min+gzip.
  • Document Parser: @llamaindex/liteparse-wasm + browser DecompressionStream('deflate-raw') + DOCX zip extraction.
  • Client Storage: native IndexedDB with a lightweight wrapper; reference URLs in localStorage.
  • Search Engine: custom client-side BM25 (bm25.ts).
  • Web Search Client: keyless Tavily (src/lib/tavilySearch.ts, X-Tavily-Access-Mode: keyless) with DuckDuckGo HTML fallback.
  • Live Voice SDK: @google/genai ^2.30.0 — browser WebSocket duplex audio (ai.live.connect) and subagent generation.
  • Crypto: Web Cryptography API (window.crypto.subtle) — AES-GCM-256, non-extractable keys in IndexedDB.
  • Testing: Vitest + React Testing Library — strictly hermetic (no network).
  • Hosting: Cloudflare Pages — zero server overhead.

Where It Runs and How Someone Tries It

  • Runtime: browser-only static app; no runtime backend.
  • Local dev: npm run dev → http://localhost:5173.
  • Production build: npm run build → dist/.
  • Deploy: Cloudflare Pages (direct dist/ upload or Wrangler).
  • Tests: npm run test (isolated Vitest suite).

Look and Feel

  • Theme: dual-theme (Light = warm paper/navy ink; Dark = rich warm dark ink) with a dynamic transparent logo and favicon.
  • Typography: sans-serif for navigation/controls; monospace for code blocks, chat metadata, and WebMCP logs.
  • Layout: strict 20% sidebar / 80% workspace.
  • Dividers: subtle borders (border-slate-700 dark, border-slate-200 light).
  • Initial state: canvas and chat render blank on load.

Components

1. App

Root container orchestrating the 20/80 layout, theme state, and WebMCP provider initialization. Delegates to three controller hooks: useSessionController (session ID, turns, messages, highlights, elapsed time, history modal, PDF export), useDocumentController (file validation < 2MB, LiteParse extraction, BM25 indexing, lazy chunk rehydration, lexical search), and useVoiceOrchestrator (Gemini Live duplex voice, subagent dispatch via VoiceBridge, hardware preflight, encrypted settings).

2. Sidebar

Hosts Branding (title, theme-aware logo, 2-tier action cluster), FileUpload (dropzone < 2MB with "Indexed" badge + drag-over highlight), ReferenceUrls (up to 10 probe-verified links), Session Highlights (starred messages), and the session strip (messages · highlights · minutes + tips re-opening the WelcomeModal).

3. CanvasArea

Top 60% pane. Toolbar (New Session, Fit View, Reset View, Export PDF, Clear Canvas) and CanvasEngine: reactive Canvas2dShape[] scene graph, fitToContent auto-centering, drag-to-pan, cursor-pinned wheel zoom, perimeter-docked connectors with pill badges, 2.5D shadows, live theme sync (getTheme + MutationObserver), medium dark yellow (#d97706) bold labels at topCenter, adaptive theme strokes, HiDPI scaling, snapshot capture. Rough.js sketching, cubic Bézier connectors, paper backdrops, and Risograph color harmonies.

4. ChatArea

Bottom 40% pane + full-screen reader popup. Lora serif feed (A-/A+ 15/17/19px, 1.75 line-height, ~72ch), humanized markdown rendering, symbol humanization with whitespace-pre-line sequence preservation and currency protection, 2px reading-progress bar, popup maximize (⤢/Escape), per-message ☆/★ + copy, thinking pulse, 0.18s entrance fades, auto-scroll, and a multi-line textarea (Enter to submit, Shift+Enter for newline).

5. NotificationModal

Popup showing rejection details when a file is ≥ 2MB or unsupported.

6. WelcomeModal

First-load how-to-use popup (shown while localStorage['b_onboarded'] is unset; dismissal persists). Six numbered steps over the warm paper token surface: upload a document → connect your AI agent (WebMCP) → ask questions → star key answers → read comfortably (A-/A+, expand) → export the session PDF. "Get started" or backdrop click dismisses; the sidebar "tips" link re-opens it.

7. HistoryModal

Lists past sessions from IndexedDB with session ID, turn counts, initial-question preview, and timestamps; actions Restore, Export PDF, and Delete.

8. WebMCPProvider

Central service registering and dispatching all 18 tools across six surfaces (document.modelContext, navigator.modelContext + modelContextTesting, window.webmcp, hidden DOM forms, webmcp:ready/modelcontext:ready events, and postMessage JSON-RPC 2.0), forwarding readOnlyHint for read-only tools (see prd.md > 5. WebMCP Tool Suite).

9. pdfExportService

In-browser report engine: blank-session guard (triggers NotificationModal), LLM markdown humanizer (H1–H6 sizing, lists, Courier code blocks, blockquotes, inline-token stripping), multilingual Indic rendering (Bengali/Hindi via Canvas2D shaping into jsPDF), and sequential turn-by-turn pagination with canvas snapshots.

10. symbolHumanizer

Dedicated string-normalization module: humanizeSymbols() maps LaTeX arrows/relations/arithmetic to clean Unicode for the UI (preserving currency); humanizeSymbolsForPdf() maps to ASCII (->, =>, !=, …) for jsPDF core fonts.

11. tavilySearch

Standalone module (src/lib/tavilySearch.ts) querying https://api.tavily.com/search with X-Tavily-Access-Mode: keyless, returning { title, snippet, url, score }; backed by the DuckDuckGo fallback in /api/websearch.

12. src/voice/ Module Suite

Self-contained voice package: types/provider.ts (ILiveVoiceProvider / ISubagentProvider), config/cryptoStorage.ts (AES-GCM-256 vault), config/modelRegistry.ts (defaults gemini-3.8-live + gemini-3.5-flash-lite), prompts.ts, audio/{recorder,player}.ts (16 kHz in / 24 kHz out), five provider implementations + subagentFactory.ts, bridge/{voiceBridge,toolAdapter}.ts, tasks/taskManager.ts, utils/jsonRepair.ts, hooks/{useVoiceAgent,useVoiceSettings}.ts, and the HUD/modals components.

13. ddgSearch (DuckDuckGo fallback parser)

src/lib/ddgSearch.ts scrapes https://html.duckduckgo.com/html/ and returns { title, snippet, url }[]. Split into a pure, exported parseDdgHtml(html, limit) (block-scoped anchor+snippet pairing, ad/redirect filtering, http(s)-only URLs after uddg unwrapping, tag stripping + named/numeric entity decoding) and a thin searchDuckDuckGo() fetch wrapper (browser-like headers; blank query → []; throws on non-OK or a challenge/bot-wall page so /api/websearch reports unavailable: true).

Data Model

IndexedDB — bAssistantDB

  • documents: id, name, size (< 2MB), pageCount, createdAt.
  • chunks: id, docId, pageNumber, text, tokens.
  • bm25_index: id (default_index), docCount, avgDocLength, docLengths, invertedIndex.
  • session_turns: id (turn_<timestamp>_<rand>), sessionId, turnNumber, userPrompt?, agentMessage?, canvasSnapshot?, canvasShapes?, timestamp.
  • session_meta: key (active_session_id) → value.

IndexedDB — bassistant_secure_vault

  • bassistant_keys: id (bassistant_device_master_key_v1), key (non-extractable 256-bit AES-GCM master key).

Application State (React / localStorage)

  • theme → b_theme; apiKey → bassistant_gemini_api_key; openaiKey → bassistant_openai_api_key (both __BASSISTANT_ENC__:v1:<iv>:<cipher>); userPreferences → b_user_preferences; liveModel → bassistant_voice_live_model; subagentModel → bassistant_subagent_model; studioVoice → bassistant_studio_voice.

External Services and Dependencies

  • Tavily Search API: POST https://api.tavily.com/search with X-Tavily-Access-Mode: keyless. Free, zero auth.
  • DuckDuckGo HTML search: server-side scrape of https://html.duckduckgo.com/html/?q={query} from the dev middleware or Cloudflare Function (never the browser). Free, zero auth; rate-limited from datacenter IPs.
  • ArXiv API: https://export.arxiv.org/api/query?search_query=all:{query}&max_results=5. Free, zero auth.
  • Gemini Live WebSocket (@google/genai): direct client-side duplex audio (ai.live.connect).
  • Cloudflare Pages: free static hosting.

Important Failure Modes

  • File ≥ 2MB or invalid format: caught by the file validator in FileUpload.tsx; triggers NotificationModal and leaves state untouched.
  • Blank export attempt: caught by handleExportPdf / pdfExportService; alerts the user and returns an error for the export_pdf tool.
  • WASM initialization delay: the dropzone shows a loading spinner until the parser is ready.
  • External search network failure: an unreachable search returns a clean error object rather than failing silently.
  • DuckDuckGo challenge / bot-wall: searchDuckDuckGo throws; /api/websearch converts it into HTTP 502 { results: [], unavailable: true, error } — a blocked fallback is never reported as a successful empty result.

What Was Simplified and Why

  • BM25 in-browser lexical search instead of cloud vector embeddings — keeps documents 100% private, avoids API keys/costs, and runs instantly in IndexedDB.
  • HTML canvas drawing primitives instead of generative image AI — instant diagrams at zero cost via lightweight tool calls.
  • Unified in-browser WebMCP bridge instead of a custom in-page inspector UI — external extensions and agents plug in natively.

Decisions and Open Issues

Learner Decisions

  • Build stack: React + Vite SPA. Deployment: Cloudflare Pages.
  • Ingestion: LiteParse (WASM) pagewise chunking + BM25 in IndexedDB (< 2MB Doc/PDF).
  • WebMCP: multi-standard support (document.modelContext, navigator.modelContext, window.webmcp, DOM forms, postMessage).
  • Documentation: docs7, README.md, CLAUDE.md, AGENTS.md.
  • Development rules: token efficiency, hermetic tests only, no subagents without permission, never read .env, only git status.
